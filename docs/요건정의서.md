# MeetStudy 요건정의서

- 작성일: 2026-11-12
- 상태: 초안 (사용자 인터뷰 기반)
- 패키지: `com.wjthinkbig.meetstudy.student`, `com.wjthinkbig.meetstudy.teacher`

> 표기: **[결정]** = 사용자가 인터뷰에서 정한 사항, **[Claude 판단]** = 구현자가 정한 기본값(변경 가능)

---

## 1. 목적과 배경

학생이 공부하는 모습을 패드나 휴대폰 카메라로 비추고, 얼굴 인식으로 "자리에 있는지, 집중하는지"를 자동으로 판정해 **선생님에게 실시간으로 공유**합니다. 공부가 끝나면 리포트, 별 보상, 문제집 사진 인증으로 동기를 부여합니다.

성공 기준:
- 학생이 자리를 비우면 **학생 화면과 선생님 화면에 동시에(체감 2초 이내)** 표시된다.
- 순공부 시간이 정확하게 쌓이고, 끝난 뒤 이탈 내역을 리포트로 확인할 수 있다.
- 문제집이 아닌 사진(빈 종이, 모니터, 사람 등)으로는 인증되지 않는다.

비목표(이번 범위 아님):
- 공부 영상 녹화나 저장 **[결정: 녹화 안 함]**
- 선생님 음성, 텍스트 메시지, 채팅 **[결정: 영상 보기 전용]**
- 보호자 앱 계정, 알림톡이나 SMS 자동 발송
- 학원 단위 B2B 관리자 기능
- 7명 이상의 대규모 방

반목표(기술적으로 동작해도 실패로 보는 경우):
- 문제집을 보느라 고개를 숙였는데 딴짓으로 찍혀서 학생이 억울한 경우(오탐)
- 얼굴 생체정보가 서버로 전송되는 경우

## 3. 기술 스택 **[결정]**

| 영역 | 선택 |
|---|---|
| 앱 | Kotlin Multiplatform + **Compose Multiplatform** (UI 공유). 학생앱과 선생님앱은 별도 앱이고 `shared` 모듈을 공유합니다 |
| 플랫폼 | Android 먼저 개발하고 검증합니다. iOS는 actual 구현과 Xcode 프로젝트까지 작성하고, 빌드와 검증은 나중에 Mac에서 합니다 |
| 백엔드 | Firebase: Auth, Firestore, Storage, Cloud Functions, FCM, Hosting |
| 실시간 영상 | **LiveKit Cloud** (SFU). 접속 토큰은 Cloud Functions가 발급합니다 |
| 카메라·ML | 기기에서 처리합니다(expect/actual) — 아래 표 참고 |

카메라와 ML 구현 **[Claude 판단]**:

| 기능 | Android | iOS |
|---|---|---|
| 얼굴 검출, 고개 각도, 눈 뜸 확률 | ML Kit Face Detection (classification, Euler angles) | Vision `VNDetectFaceLandmarksRequest` / 롤·요 각도 |
| 본인 확인 임베딩 | MobileFaceNet TFLite (기기 내) | 동일 모델 TFLite 또는 CoreML 변환 |
| 상체(사람) 감지 – 얼굴 미검출 시 보완 | ML Kit Pose Detection | Vision `VNDetectHumanBodyPoseRequest` |
| 폰 사용 감지 | TFLite EfficientDet-Lite0 (COCO `cell phone`) | 동일 모델 |
| 문제집 사각형 검출 | OpenCV 윤곽선 → 사각형 근사 | Vision `VNDetectRectanglesRequest` |
| 글자 존재 확인 | ML Kit Text Recognition (Korean) | Vision `VNRecognizeTextRequest` |
| 공유 라이브러리 | GitLive `firebase-kotlin-sdk` | 동일 |
| 로컬 저장 | SQLDelight (세션 이벤트 버퍼), 기기 암호화 저장소(얼굴 임베딩) | 동일 + Keychain |

- 카메라 프레임 하나를 **LiveKit 송출과 ML 분석에 같이** 씁니다. Android는 LiveKit의 VideoProcessor로 프레임을 가로채고, iOS는 커스텀 capturer를 씁니다. 감지 처리는 약 5fps로 제한해 발열과 배터리 소모를 줄입니다.

## 4. 학생앱 기능

### 4.1 가입과 로그인 **[결정]**
- 아이디/비밀번호, 카카오, Google, Apple 로그인
  - 카카오는 Cloud Functions에서 커스텀 토큰으로 연동합니다.
  - 아이디는 선생님이 학생을 찾는 데 쓰이므로 고유해야 합니다.
- 소셜로 가입했더라도 **고유 아이디(닉네임 ID)를 반드시 정해야** 합니다 **[Claude 판단]**

### 4.2 얼굴 등록 (최초 1회) **[결정]**
- 정면, 좌우 약간 돌린 모습 등 5장을 찍어 평균 임베딩을 만듭니다.
- 임베딩은 **기기의 암호화 저장소에만** 둡니다. 서버로 보내지 않고, 원본 사진은 저장하지 않습니다.
- 기기를 바꾸거나 앱을 재설치하면 다시 등록합니다. 설정에서 등록을 삭제하거나 다시 등록할 수 있습니다.
- 보호자 동의: **MVP에서는 동의 체크 화면으로 대신합니다 [결정: 동의는 나중에]**.
  - ⚠️ 출시 전 필수: 만 14세 미만은 영상 처리에 대해 법정대리인 동의를 받아야 합니다(라이브 영상이 서버를 거쳐 선생님에게 전송됨). 출시 차단 항목으로 관리합니다.

### 4.3 자리 확인 캘리브레이션 (매 세션) **[결정]**
1. **본인 확인**: 기기를 들고 얼굴을 비추면 등록된 임베딩과 비교합니다. 유사도가 임계값 미만이면 "본인이 아닙니다"를 표시하고 진행을 막습니다.
2. **카메라 거치 안내 페이지** **[결정]**: 본인 확인이 끝나면 기기를 어디에 어떻게 두는지 **재미있는 애니메이션**으로 보여줍니다. 거치 위치는 책상 앞 모서리, **정면~45도 비스듬히** **[결정]**입니다.
   - 애니메이션 장면: ① 캐릭터가 패드/폰을 들고 책상으로 감 → ② 책상 앞 모서리에 거치대를 두고 45도로 돌림 → ③ 화면 속 카메라 시야(부채꼴)에 얼굴과 책이 함께 들어오며 반짝 → ④ 엄지척. 무한 반복합니다.
   - 체크 포인트 3개를 텍스트로 함께 보여줍니다: "얼굴과 책이 같이 보이게", "팔 길이만큼 떨어뜨려서", "밝은 곳에서, 충전기 연결".
   - 화면 하단에 작은 실시간 카메라 미리보기와 상태("얼굴 인식됨 ✓")를 띄워, 거치하면서 바로 확인할 수 있게 합니다. **[Claude 판단]**
   - 페이지 하단의 **[공부 시작]** 버튼은 얼굴이 미리보기 안에 인식되어 있을 때만 활성화됩니다. **[Claude 판단]**
   - 구현: 일러스트 레이어(PNG/벡터)를 Compose 애니메이션(이동, 회전, 페이드)으로 움직입니다. 이미지 생성 프롬프트는 [docs/image-prompts.md](image-prompts.md)에 있습니다. **[Claude 판단: Lottie 대신 Compose 애니메이션, 의존성 추가 없음]**
3. **[공부 시작]**을 누르면 "평소처럼 문제집을 봐요"라고 안내하고 3초 동안의 자세를 **시작 기준 자세**로 저장한 뒤 타이머를 시작합니다. 캘리브레이션은 카메라 위치를 잡는 용도라서 **실패하지 않습니다** **[결정 2026-11-13]**: 얼굴이 잘 안 잡히거나 화면(카메라)을 보고 있으면 기본 독서 자세(카메라 앞에서 고개를 숙인 자세)로 시작하고, 실제 공부 방향은 공부 중 스스로 학습으로 맞춥니다.
   - **카메라 이동 시 재캘리브레이션** **[결정 2026-11-13]**: 공부 중 기기 기울기가 10도 이상 바뀐 채로 2초가 지나면(거치대를 옮기거나 다시 세운 경우) "카메라가 움직였어요"를 표시하고 3초 동안 기준 자세를 다시 잡습니다. 이전 카메라 위치에서 배운 공부 방향은 지웁니다. 기울기 변화 없이 책상 위에서 밀기만 한 경우는 아직 잡지 못합니다.
4. 조명이 너무 어둡거나 얼굴이 너무 작으면(너무 멀면) 안내하고 다시 시도하게 합니다.

### 4.4 공부 세션
- 시작할 때 **목표 순공부시간**을 정합니다 **[결정]**. 공부 중일 때만 타이머가 흐르고, 목표를 채우면 자동으로 끝납니다.
  - 선생님 방은 학생이 시작할 때 목표를 정합니다(선생님이 고정하지 않음). **[Claude 판단]**
- 모드:
  - **선생님 방 모드**: LiveKit 송출, 상태 동기화, 학생끼리도 서로 보기 **[결정]**
  - **혼자 공부 모드** **[결정]**: 감지, 타이머, 리포트, 별, 인증은 같고 LiveKit만 연결하지 않습니다. 리포트는 연결된 선생님에게도 전달됩니다.
- 공부 중에는 화면 꺼짐을 막고, 충전을 권장하는 안내를 보여줍니다.
- **휴식 버튼** **[결정]**: 선생님이 정한 횟수와 시간 한도 안에서 쓸 수 있습니다(혼자 모드 기본값은 3회, 회당 10분 **[Claude 판단]**). 휴식 중에는 타이머가 멈추고 딴짓으로 집계하지 않습니다. 한도를 넘으면 자리 비움으로 바뀝니다.
- 중도 종료: "공부 끝내기"를 누르면 확인한 뒤 리포트로 갑니다.

### 4.5 상태 판정 규칙

| 상태 | 판정 | 지속 기준 |
|---|---|---|
| 공부 중 | 본인 얼굴이 있고, 기준 자세나 **스스로 익힌 공부 방향** 중 하나의 범위 안 | – |
| 자리 비움 | 얼굴도 사람(상체)도 검출되지 않음 **[결정: 상체 감지로 보완]** | 선생님이 방별로 설정 **[결정]**, 기본 10초. 혼자 모드는 10초 |
| 고개 돌림/다른 곳 응시 | 기준 대비 yaw가 ±35°를 넘거나 pitch가 위쪽으로 크게 벗어남 | 15초 **[결정: 유형별 기본값]** |
| 카메라 응시 | 얼굴이 이 기기(카메라·타이머 화면)를 정면으로 봄(yaw, pitch 모두 ±12° 안). 공부 대상은 책이나 다른 기기이므로 공부가 아님 **[결정 2026-11-13]** | 10초 (타이머를 잠깐 보는 것은 허용) |
| 졸음/엎드림 | 양 눈 뜸 확률 < 0.3, 또는 얼굴이 기준보다 크게 아래로 내려가 엎드린 자세 | 20초 |
| 폰 사용 | 프레임 안에서 폰 검출 + 손이나 얼굴 근처에 있음 | 10초 |
| 앱 이탈 | 앱이 백그라운드로 감 | 즉시 **[결정: 딴짓(기기 사용)으로 기록]** |
| 휴식 | 학생이 휴식 버튼을 누름 | – |

- **공부 방향 스스로 학습** **[결정 2026-11-13]**: 공부 중이거나 다른 곳을 보는 동안의 고개 방향을 모아, 같은 방향을 모두 합쳐 3분 이상 본 경우 공부 방향으로 익힙니다(예: 옆에 둔 다른 태블릿). 카메라를 보는 방향은 배우지 않습니다. 익힌 방향은 각도 숫자만 기기에 저장해 다음 공부에도 이어서 쓰며, 홈 화면의 "공부 자세 다시 배우기"로 초기화합니다. 한 방향을 3분 넘게 멍하니 보면 그 방향도 배울 수 있는 한계가 있습니다.
- 문제집을 보느라 고개를 숙이는 것은 기준 자세의 pitch 허용 범위 안이면 **공부 중으로 판정**합니다(오탐 방지가 최우선).
- **얼굴이 안 보일 때 보완** **[결정]**: 얼굴이 사라지면 상체 감지로 전환합니다(Android ML Kit Pose Detection, iOS Vision `VNDetectHumanBodyPoseRequest`, 약 2fps). 기준 자세 위치에 어깨와 머리가 있으면 "공부 중"으로 유지합니다. 직전에 얼굴이 아래쪽으로 움직이다 사라졌다면 더더욱 공부 중으로 봅니다. 사람이 아예 없을 때만 자리 비움으로 판정합니다. 상체만 보이는 동안에는 본인 확인을 미루고, 얼굴이 다시 보이면 바로 확인합니다.
- **유예 시간 소급 차감** **[Claude 판단]**: 자리 비움이나 딴짓으로 판정되면, 판정 전 대기 시간(10/15/20초)도 순공부 시간에서 빼고 이벤트 시작 시각을 그때로 되돌립니다. 화면 타이머는 판정 순간 해당 시간만큼 되돌아갑니다. 이렇게 해야 리포트 숫자가 실제와 맞습니다.
- 본인 확인은 30초마다 다시 합니다. 다른 사람이 앉아 있으면 "자리 비움"으로 처리합니다. **[Claude 판단]**
- 공부 중이 아닌 상태가 되면 타이머가 멈추고, 다시 공부 중이 되면 자동으로 재개합니다.
- 상태가 바뀌면 학생 화면에 **배너와 색 변화로만** 알립니다 **[결정]**(소리, 진동, 푸시 없음).
- 앱 이탈: 전화 수신은 "전화"라는 사유로 따로 표시합니다. iOS는 백그라운드에서 카메라를 쓸 수 없으므로, 돌아오면 다시 캘리브레이션 없이 재개합니다.

### 4.6 종료 → 보상 → 인증 화면 흐름
1. **목표 달성 화면**: 별 애니메이션과 함께 오늘 순공부 시간을 보여줍니다. 목표를 달성하면 별 1개를 줍니다 **[결정]**.
2. **"공부 인증하고 별 더 받기"** 버튼을 누르면 인증 카메라가 열립니다.
3. **인증 카메라** **[결정]**:
   - 사각형 문서를 검출하고, OCR로 글자가 일정량(10자 이상 **[Claude 판단]**) 있는지 확인합니다.
   - 조건을 만족하면 테두리 가이드가 초록색으로 바뀌고 **1초 유지 후 자동 촬영**합니다. 셔터 버튼은 없습니다.
   - 사각형 영역을 원근 보정으로 잘라서 Storage에 업로드합니다.
4. **공부 인증 완료 화면**: 인증 사진 썸네일과 별 +1을 보여줍니다. 하루 최대 2개입니다 **[결정]**.
5. 목표를 채우지 못하고 중도 종료하면 리포트를 보여주고, 인증으로 별 1개만 받을 수 있습니다 **[결정]**.
6. **공유하기** **[결정]**:
   - 이미지 카드(순공부 시간, 별, 인증 사진)를 OS 공유 시트로 보냅니다.
   - 연결된 선생님 앱에 자동으로 전송합니다(별도 조작 없음).
   - 보호자용 **웹 링크**를 OS 공유 시트(카톡, 문자 등)로 보냅니다 **[결정]**.

### 4.7 리포트 **[결정: 아래 4가지 모두]**
- 요약 수치: 총 세션 시간, 순공부 시간, 집중률(순공부/총시간), 딴짓 유형별 횟수와 시간, 휴식 횟수와 시간
- 타임라인 바: 공부(초록), 자리 비움(회색), 딴짓(주황), 휴식(파랑)
- 이벤트 목록: 예) "14:32 자리 비움 3분 10초"
- 주간/월간 추이: 누적 공부 시간, 별 개수, 연속 달성일(스트릭)

## 5. 선생님앱 기능 **[결정]**

- **선생님 가입** **[결정: 관리자 승인제]**: 선생님앱에서 가입하면(로그인 방식은 학생앱과 동일) `teacherStatus = pending` 상태가 됩니다. 운영자가 승인해야 학생 검색, 방 생성, 영상 보기가 가능합니다. MVP에서는 운영자가 Firebase 콘솔에서 승인하고, 보안 규칙과 Cloud Function이 `approved`인지 확인합니다. 한 계정은 학생이나 선생님 중 한 역할만 가집니다. **[Claude 판단]**
- **학생 등록**: 학생 아이디로 검색해 연결 요청을 보내고, 학생이 앱에서 수락하면 연결됩니다 **[결정: 선생님이 ID 검색]**. 학생은 언제든 연결을 끊을 수 있습니다.
- **여러 선생님 연결** **[결정]**: 학생 한 명이 여러 선생님과 연결될 수 있습니다. 혼자 모드 리포트는 연결된 선생님 모두에게 갑니다. 혼자 모드의 휴식 한도는 기본값(3회 × 10분)을 씁니다. 한 번에 방 하나에만 들어갈 수 있습니다.
- **방의 수명** **[Claude 판단]**: 방은 선생님이 닫을 때까지 열려 있습니다. 학생 홈에 "참여 가능한 방" 목록이 있어서, 푸시를 놓쳤거나 앱이 꺼진 경우에도 다시 들어갈 수 있습니다. 방이 닫히거나 내보내기를 당하면 학생 세션은 끊기지 않고 혼자 모드로 이어집니다.
- **방 만들기 / 방 설정**: 방 이름, 연결된 학생 중 초대할 학생(**최대 6명**), 자리 비움 판정 시간, 휴식 횟수와 시간 한도를 정합니다.
- **초대 푸시**: 방을 만들면 선택한 학생에게 FCM 푸시를 보냅니다. 학생이 푸시를 누르면 캘리브레이션을 거쳐 방에 입장합니다 **[결정]**.
- **실시간 현황**:
  - 최대 6명을 라이브 영상 그리드로 봅니다. 탭하면 크게 봅니다.
  - 각 타일에는 상태 배지(공부/자리비움/딴짓 유형/휴식/앱이탈/오프라인), 순공부 시간, 목표 대비 진행률을 표시합니다.
  - 자리 비움 배지는 학생 화면과 같은 시점에 표시됩니다.
- **리포트 열람**: 학생별 세션 리포트와 인증 사진, 주간/월간 추이를 봅니다.
- **방 종료 / 학생 내보내기**
- 선생님 화면은 영상 보기 전용입니다. 음성과 메시지는 없습니다.

## 6. 데이터와 동기화 설계 **[Claude 판단]**

Firestore 구조(초안):
```
users/{uid}            role, loginId(unique), name, birthYear, fcmTokens[]
loginIds/{loginId}     uid   // 고유성 보장
links/{teacherUid_studentUid}  status: pending|accepted
rooms/{roomId}         teacherUid, name, studentUids[], awayThresholdSec, breakLimit{count,minutes}, status: open|closed
rooms/{roomId}/presence/{studentUid}  state, since, focusedSec, goalSec, updatedAt
sessions/{sessionId}   studentUid, roomId?, mode, goalSec, startedAt, endedAt, focusedSec, events[], stars, proofPhotoPath?, shareToken
```
- 실시간 상태는 학생 기기가 **상태가 바뀔 때마다** `presence` 문서를 갱신하고, 선생님앱이 snapshot listener로 구독합니다(목표 지연 2초 이내). 순공부 시간은 30초마다 갱신합니다.
- 오프라인 판정: `updatedAt`가 60초 넘게 갱신되지 않으면 선생님 화면에 "오프라인"을 표시합니다. 학생 기기는 30초마다 heartbeat를 보냅니다.
- 세션 이벤트는 로컬(SQLDelight)에 먼저 쌓고, 종료 시 Firestore에 저장합니다. 네트워크가 끊겨도 감지와 타이머는 계속 동작합니다.
- 별은 클라이언트가 직접 쓰지 않고 Cloud Function이 검증한 뒤 지급합니다(하루 2개 제한, 목표 달성 여부 확인).
- 보호자 웹 링크: `https://<hosting>/r/{shareToken}`. 추측할 수 없는 토큰을 쓰고, 로그인 없이 리포트 요약만 보여줍니다. 인증 사진은 표시하지 않습니다.
- 보안 규칙: 학생은 자기 데이터만, 선생님은 연결된(accepted) 학생 데이터만 읽을 수 있습니다.
- LiveKit 토큰: Cloud Function이 방 멤버십을 확인한 뒤 발급합니다. 학생은 publish와 다른 학생 subscribe, 선생님은 subscribe만 할 수 있습니다.

### 6.1 기타 결정
- 문제집 인증 검사는 **MVP에서는 기기 안에서만** 합니다(사각형 + OCR). 조작된 클라이언트로 우회하는 것까지는 막지 않습니다. 필요해지면 서버 검증 Function을 추가합니다. **[Claude 판단]**
- 최소 지원 버전: **Android 8.0(API 26)**, 2020년 이후 중급 기기를 기준으로 합니다. 감지 처리 시간이 기준을 넘는 저사양 기기에서는 폰 사용 감지를 자동으로 끕니다. iOS는 15 이상입니다. **[Claude 판단]**
- 서비스 계정: Firebase, LiveKit, Apple은 있습니다. 카카오는 새로 만들 예정입니다. 키 값은 나중에 넣을 수 있도록 설정 파일 자리만 비워두고 개발합니다(`google-services.json`, `local.properties`의 LiveKit URL과 카카오 키) **[결정]**. Firebase 리전은 서울(asia-northeast3)을 기본으로 합니다. 회사의 데이터 국내 저장 규정은 출시 전에 확인합니다.

## 9. 구현 순서 **[결정: 학생 핵심 루프 먼저]**

1. **1단계 – 학생 혼자 모드 (Android)**: 프로젝트 골격(KMP, CMP), 로그인, 얼굴 등록, 캘리브레이션, 감지 엔진, 타이머, 휴식, 리포트, 별, 문제집 인증, 공유 카드

3. **3단계 – 라이브**: LiveKit 송출과 구독, 학생끼리 보기, 6명 그리드
4. **4단계 – iOS**: actual 구현 검증(Mac)
5. **출시 전**: 법정대리인 동의, 개인정보 처리방침, 스토어 심사 대응
