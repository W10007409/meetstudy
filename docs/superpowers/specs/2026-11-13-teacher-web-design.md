# 선생님 웹 + 리포트 리디자인 설계

- 작성일: 2026-11-13
- 상위 문서: [요건정의서](../../요건정의서.md) 5장(선생님앱), 4.7(리포트), 6장(데이터)
- 확정 시안: [teacher-room.html](2026-11-13-teacher-web/teacher-room.html), [report.html](2026-11-13-teacher-web/report.html) (브라우저로 열면 그대로 보입니다)

표기: **[사용자 결정]**은 사용자가 정한 것, **[Claude 판단]**은 제가 정했고 사용자가 확인하지 않은 것입니다.

## 1. 왜 만드는가

학생이 공부하는 동안 선생님이 **책상 위 PC나 태블릿**으로 방의 현황을 보고, 끝난 뒤 학생별 리포트를 확인합니다. **[사용자 결정]**
선생님은 학생에게 직접 개입하지 않습니다. 할 일은 **방 관리**(만들기, 초대, 설정, 닫기, 내보내기)와 보기뿐입니다. **[사용자 결정]**

학생 앱의 리포트는 지금 회색 카드와 글자 목록이라 밋밋합니다. 선생님 웹과 같은 디자인의 세련된 리포트로 바꿉니다. **[사용자 결정]**

## 2. 목표 / 하지 않을 것 / 실패로 볼 것

**목표**
- 선생님이 웹을 열면 왼쪽에 내 방 목록, 오른쪽에 고른 방의 학생 최대 6칸이 바로 보입니다(A안). **[사용자 결정]**
- 학생 칸의 상태가 학생 화면과 같은 시점(체감 2초 이내)에 바뀝니다. (요건정의서 1장)
- 선생님 웹과 학생 앱이 같은 리포트를 같은 디자인으로 보여 줍니다. **[사용자 결정]**

**하지 않을 것(이번 범위 밖)**
- 메시지, 음성, 알림 보내기 등 선생님의 개입 기능. **[사용자 결정]**
- 라이브 영상. 칸 안의 영상 자리는 비워 두고 3단계(LiveKit)에서 채웁니다. (요건정의서 9장)
- 보호자 웹 링크, 초대 푸시(FCM), Cloud Functions(별 검증, 카카오 로그인). Functions는 유료 요금제(Blaze)가 필요해서, 개인 계정 무료 요금제(Spark)로 돌아가는 범위만 이번에 합니다. **[Claude 판단]**
- 카카오·Google·Apple 로그인. 이번에는 아이디/비밀번호 로그인만 합니다. **[Claude 판단]**
- 선생님용 모바일 앱. 웹 하나로 PC와 태블릿을 모두 맡습니다. 요건정의서 2장의 "별도 모바일 앱"을 대체합니다. **[사용자 결정, 요건정의서 갱신 필요]**

**실패로 볼 것**
- 선생님이 학생을 감시하는 도구처럼 보이는 것: 빨간 경고, 깜빡임, 소리, 학생 순위 비교는 넣지 않습니다. **[Claude 판단]**
- 학생 화면은 '자리 비움'인데 선생님 화면은 아직 '공부 중'인 상태가 2초 넘게 이어지는 것.

## 3. 제약

- 상태 색: 공부 #4CC38A, 자리 비움 #9AA3AE, 딴짓(다른 곳 봄, 카메라 응시, 졸음, 폰, 앱 이탈) #FF9F43, 휴식 #5AA9FF, 오프라인 #FF6B6B. 학생 앱 [StateColors.kt](../../../shared/src/commonMain/kotlin/com/wjthinkbig/meetstudy/ui/theme/StateColors.kt)와 같아야 합니다. (요건정의서 7장)
- 상태 이름도 학생 앱 `stateLabel`과 같은 말을 씁니다(예: "다른 곳 보는 중", "카메라 보는 중").
- 개인정보: 얼굴 임베딩과 영상은 서버로 보내지 않습니다. 선생님 웹이 받는 것은 상태, 시간, 세션 기록, 인증 사진뿐입니다. (요건정의서 6장, 8장)
- 화면: PC(1280px 이상)와 태블릿 가로가 기본입니다. 폰 세로에서도 깨지지 않게 한 줄로 쌓습니다(시안에 반응형 포함).
- 선생님 가입은 관리자 승인제입니다(`teacherStatus = pending → approved`). 승인 전에는 "승인을 기다리고 있어요" 화면만 보입니다. (요건정의서 5장)
- 방 인원은 최대 6명입니다.

## 4. 정해진 방식

### 4.1 기술 **[Claude 판단, 사용자에게 알림]**
- 선생님 웹은 **React + TypeScript + Vite**로 만듭니다. Firebase JS SDK와, 3단계에서 쓸 LiveKit JS SDK가 웹에서 가장 안정적이기 때문입니다.
- 저장소 안 새 디렉터리 `teacherWeb/`에 둡니다.
- 학생 앱 리포트는 기존 Compose(Kotlin) 코드에서 다시 그립니다.

### 4.2 디자인 언어 (두 화면 공통) **[사용자 결정: A+C 혼합, 디자인 스킬로 다듬은 시안 확정]**
- 바탕은 시원한 노트 종이색 #F5F7F6, 글자는 #18212B / #56626F / #9AA5B1, 구분선은 #E3E8E6입니다.
- 강조색은 청록 #1F8A82 하나와 형광 노랑 #FFE45C 하나입니다. 노랑은 '연속 달성' 같은 칭찬 한 곳에만 씁니다.
- 글꼴은 IBM Plex Sans KR 한 가지입니다. 학생 앱은 같은 글꼴을 Compose 리소스로 넣습니다.
- 카드 남발 금지: 요약은 종이 위에 바로 놓고, 하얀 시트(그림자)는 '공부 시간표'와 학생 칸에만 씁니다.
- 대문자 라벨, "A · B · C" 식 메타 문자열, 화살표 붙은 버튼 문구는 쓰지 않습니다. 문장은 짧은 존댓말("53분 동안 집중했어요")로 씁니다.
- 움직임은 리포트를 열 때 집중률 링이 한 번 채워지는 것 하나뿐입니다. 모션 줄이기 설정을 존중합니다.

### 4.3 공부 시간표 (두 화면의 공통 핵심 요소) **[사용자 결정: 시안 승인]**
- 학생들이 스터디 플래너에 칠하는 방식을 그대로 씁니다. 한 줄이 1시간, 한 칸이 10분이며, 칸 안을 1분 단위로 상태 색으로 칠합니다. 세션 밖의 분은 빈칸(#EEF2F1)입니다.
- 리포트에서는 세션이 걸친 시간 줄을 모두 그립니다.
- 선생님 방의 학생 칸에서는 **지금 시간 한 줄**만 작게 그립니다.

### 4.4 선생님 웹 화면

**① 방 화면(첫 화면)**: [teacher-room.html](2026-11-13-teacher-web/teacher-room.html)
- **왼쪽 내비게이션**
  - 선생님 이름과 연결된 학생 수
  - 열린 방 / 닫힌 방 목록
  - "+ 방 만들기"
  - 아래쪽에 "학생 연결 관리"(대기 중인 요청 수 표시)와 "학생 리포트"
- **방 머리**
  - 방 이름
  - 한 문장 설명("1시간 12분째 열려 있어요. 자리 비움은 10초, 휴식은 3번까지 10분씩이에요.")
  - 버튼: 학생 초대(주 버튼), 방 설정, 방 닫기(빨간 글자)
- **요약 한 줄**: "3명 공부 중 · 1명 딴짓 · 1명 오프라인"
- **학생 칸**: 3열, 태블릿에서는 2열, 폰에서는 1열입니다.
  - 영상 자리
  - 이름과 상태 배지(딴짓·휴식은 지속 시간이나 남은 시간 포함)
  - "37분 공부했어요 · 목표 60분"
  - 이번 시간의 시간표 한 줄
  - 딴짓 칸은 영상 자리에 주황 테두리, 자리 비움 칸은 회색 테두리를 둡니다.
  - 빈 자리는 점선 "+ 학생 초대하기 (N자리 남음)"입니다.
- **칸을 누르면** 그 학생의 오늘 리포트가 열립니다. **[Claude 판단]**
- **오프라인 판정**: presence `updatedAt`가 60초 넘게 멈추면 오프라인입니다. (요건정의서 6장)

**② 방 만들기 / 방 설정**: 같은 폼을 씁니다.
- 방 이름
- 초대할 학생: 연결된 학생 중 최대 6명
- 자리 비움 판정 시간: 기본 10초
- 휴식 횟수와 회당 시간: 기본 3회 × 10분

**③ 학생 연결 관리**
- 학생 아이디로 검색하고 연결 요청을 보냅니다.
- 보낸 요청은 대기 / 수락됨으로 보입니다.
- 연결된 학생 목록에서 연결을 끊을 수 있습니다.
- 학생은 학생 앱에서 수락합니다. (요건정의서 5장)

**④ 학생 리포트**
- 연결된 학생 목록에서 고르면 리포트(아래 4.5)가 열립니다.
- 날짜별 세션 목록에서 다른 세션도 고를 수 있습니다.

**⑤ 로그인 / 승인 대기**
- 로그인 방식은 학생 앱과 같습니다(요건정의서 4.1).
- 승인 전에는 대기 화면을 보여 줍니다.

  - 지난번 세션이 없으면 비교 문장을 생략합니다.

### 4.6 데이터
- 구조는 요건정의서 6장(`users`, `loginIds`, `links`, `rooms`, `rooms/{id}/presence`, `sessions`)을 따릅니다.
- **Firebase 키가 오기 전에도 화면을 만들고 확인할 수 있게**, 선생님 웹의 데이터 접근은 하나의 인터페이스 뒤에 둡니다. 구현은 두 가지입니다. **[Claude 판단]**
  - **mock 구현**: 시안의 학생 5명, 방 3개, 세션 기록을 내장합니다. presence는 몇 초마다 상태가 바뀌어 실시간처럼 보입니다.
  - **Firebase 구현**: Firestore snapshot listener를 씁니다.
  - 어느 쪽을 쓸지는 환경 변수로 고릅니다.
- 리포트 계산(집중률, 흐트러진 시간, 일별 합계, 연속 달성일)은 학생 앱 Kotlin과 같은 결과를 내야 합니다. 웹 쪽은 TypeScript로 다시 구현하고, 같은 입력·같은 출력의 테스트 케이스를 양쪽에 둡니다. **[Claude 판단]**

### 4.7 데이터 세부 결정 **[Claude 판단: 빌더 검토에서 나온 질문을 정리한 것]**
- **세션 문서 모양**
  - Kotlin [SessionRecord](../../../shared/src/commonMain/kotlin/com/wjthinkbig/meetstudy/data/SessionRecord.kt)를 기준으로 합니다: `segments[{state, startMs, endMs}]`(epoch ms, `FocusState` 이름 문자열), `goalMs`, `goalStar`, `proofStar`.
  - 여기에 `studentUid`, `roomId?`, `proofPhotoPath?`를 더합니다.
  - 요건정의서 6장의 `events[]`, `stars`는 초안이며 `segments`와 두 boolean으로 대체합니다.
- **날짜 경계**: 모든 일별 계산(주간 막대, 연속 달성일, '오늘', 지금 시간 줄)은 **Asia/Seoul**로 고정합니다. 국내 서비스라서, 선생님과 학생의 기기 시간대가 달라도 같은 날로 묶입니다.
- **"지난번" 비교**: 같은 학생의 바로 이전 세션(날짜 무관)과 비교합니다.
- **학생 앱 주간 / 월간 탭**: 학생 앱에 이미 있으므로 새 디자인으로 함께 다시 그립니다.
- **방 문서**
  - `rooms/{id}`에 `openedAt`, `closedAt?`, `status: open|closed`, `awayThresholdSec`, `breakLimit{count, minutes}`를 둡니다.
  - **방 닫기**는 `status = closed`로 바꾸는 것입니다. 학생 세션은 끊기지 않고 혼자 모드로 이어집니다(요건정의서 5장).
  - 학생 앱은 방에 들어올 때 방의 판정 시간과 휴식 한도를 읽어 씁니다.
- **학생 칸의 시간표 줄**
  - presence 문서에 지금 세션의 `segments`(상태가 바뀔 때마다 갱신, 상태 변경 때 어차피 쓰므로 추가 쓰기 없음)와 `sessionStartMs`를 둡니다.
  - 그래서 선생님이 페이지를 늦게 열어도 이전 구간까지 보입니다.
- **배포**: Firebase Hosting(요건정의서 6장의 Hosting과 같은 곳)에 올립니다. Gradle 빌드와는 연결하지 않고, `teacherWeb/`에서 `npm run build`로 따로 빌드합니다.
- **승인 상태**: `users/{uid}.teacherStatus`를 실시간으로 구독합니다. 운영자가 승인하면 다시 로그인하지 않아도 화면이 바뀝니다.
- **인증 사진**
  - Firebase Storage `proofs/{studentUid}/{sessionId}.jpg`에 둡니다.
  - 보안 규칙상 연결(accepted)된 선생님만 읽을 수 있습니다.
- **글꼴**: IBM Plex Sans KR은 OFL 라이선스라 자유롭게 넣을 수 있습니다. 웹은 Google Fonts로 불러오고, 학생 앱은 Compose 리소스로 같이 넣습니다.

### 4.8 Firebase 연동 (이번 범위에 포함) **[사용자 결정: 포함, 사용자 개인 Firebase 계정]**
- **대상**: 선생님 웹과 학생 앱이 모두 같은 Firebase 프로젝트에 붙습니다. mock 구현은 개발과 화면 확인용으로 남겨 둡니다.
- **로그인 (아이디/비밀번호)** **[Claude 판단]**
  - Firebase Auth의 이메일/비밀번호를 쓰고, 이메일 자리에는 `{아이디}@id.meetstudy.app` 같은 내부 주소를 넣습니다. 사용자에게는 아이디만 보입니다.
  - 아이디 고유성은 `loginIds/{아이디}` 문서를 "없을 때만 만들기" 보안 규칙으로 보장합니다(Functions 불필요).
  - 가입할 때 학생 / 선생님 역할을 고릅니다. 선생님은 `teacherStatus = pending`으로 시작하고, 운영자(사용자)가 Firebase 콘솔에서 `approved`로 바꿉니다.
- **학생 앱에 새로 필요한 것**
  - 로그인 / 가입 화면
  - 홈의 "선생님 연결 요청" 목록(수락 / 거절, 연결 끊기)
  - 홈의 "참여할 수 있는 방" 목록과 방 입장. 방 입장은 혼자 모드와 같은 흐름이고, 방의 자리 비움 시간과 휴식 한도를 씁니다.
  - presence 올리기: 상태가 바뀔 때마다, 그리고 30초마다 heartbeat를 보냅니다(요건정의서 6장).
  - 세션이 끝나면 `sessions`에 저장합니다. 혼자 모드 세션도 연결된 선생님이 볼 수 있게 올립니다.
  - 로컬 저장(SessionStore)은 그대로 두고, 오프라인이면 나중에 다시 올립니다.
- **별**: Functions 없이 학생 앱이 지금처럼 계산해 `goalStar`, `proofStar`로 올립니다. 조작된 앱까지는 막지 않습니다. 유료 요금제로 바꾸면 Function 검증으로 옮깁니다. **[Claude 판단]**
- **보안 규칙 (Firestore)**
  - 학생은 자기 문서만 쓰고 읽습니다.
  - 선생님은 `links/{teacherUid_studentUid}.status == accepted`인 학생의 presence와 sessions만 읽습니다.
  - 방은 만든 선생님만 씁니다.
  - 승인되지 않은 선생님은 학생 검색, 방 만들기, 읽기를 할 수 없습니다.
  - 규칙 테스트는 Firebase 에뮬레이터로 합니다.
- **리전**: Firestore는 서울(asia-northeast3)에 둡니다(요건정의서 6.1).
- **키와 설정 파일**: 채팅으로 주고받지 않습니다.
  - 학생 앱: 사용자가 `studentApp/google-services.json`을 직접 넣습니다.
  - 선생님 웹: 사용자가 `teacherWeb/.env.local`에 웹 설정값을 직접 넣습니다.
  - 두 파일 모두 git에서 제외합니다.
  - 배포용 `firebase login`도 사용자가 직접 실행합니다.

- **인증 사진** **[사용자 결정: 선생님 화면에도 보여야 함]**
  - 학생 앱이 세션을 올릴 때 사진도 Storage에 올립니다(4.7의 경로와 규칙).
  - 새 Firebase 프로젝트의 Storage는 **Blaze 요금제**에서만 만들 수 있으므로, 사용자가 프로젝트를 Blaze로 바꿉니다. 무료 사용량 안에서는 요금이 거의 없습니다.
  - Blaze가 되면 Cloud Functions도 쓸 수 있지만, 이번 범위(4.8)는 그대로 둡니다.
  - 사진 업로드가 실패해도 세션 기록 업로드는 막지 않고, 사진만 나중에 다시 올립니다.
- **지원 환경**
  - 선생님 웹: Chrome / Edge 107 이상, Safari 16 이상
  - 학생 앱: Android 8.0 이상(권장 Android 10 이상)
  - iOS: 15.5 이상(4단계)
